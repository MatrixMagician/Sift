## 4. Finding: `sift eval` gate fails on a sampling-nondeterministic endpoint

Run live against the operator's Lemonade instance, `sift eval` reports
`GATE: FAIL` on three of five floors:

```
  retrieval_hit_rate        1.00 >=  0.80  PASS
  hypothesis_hit_at_k       0.86 >=  1.00  FAIL
  citation_validity_rate    1.00 >=  1.00  PASS
  determinism_stability     0.00 >=  1.00  FAIL
  eustack_detection_rate    1.00 >=  1.00  PASS
  false-positive negatives: negative-no-incident
```

### Root cause — the endpoint, not v1.3

The backing llama-server (`127.0.0.1:8002`) serves, in its own `/props`:

```
default_generation_settings.params.seed        = 4294967295   (random)
default_generation_settings.params.temperature = 0.8
```

Sift sends **neither** `seed` nor `temperature` in its chat payload (verified in
`client.chat`: the body carries only `messages`, `model` and an optional
`response_format`), so the endpoint's loaded sampler settings fully determine
reproducibility.

Demonstrated directly — three **identical** prompts to that endpoint returned
three different completions:

```
call 0: 1. Running memory-intensive applications 2. Multiple browser tabs 3. Background processes
call 1: 1. Running memory-intensive applications 2. Open file handles pointing to large datasets 3
call 2: 1. Running memory-intensive applications 2. Open file handles pointing to large files 3. M
```

`determinism_stability` is by definition 1.0 only if repeated runs are
byte-identical, so a random-seeded endpoint at temperature 0.8 scores 0.00
necessarily. The other two failures are downstream of the same sampling:
`memory-watermark-cascade` missed an acceptable keyword on this draw, and
`negative-no-incident` emitted a confident hypothesis on healthy logs.

**This is not a v1.3 regression.** The three eu-stack floors — the ones v1.3
actually added — all **PASS**, and they are LLM-free by construction
(`eustack_detection_rate 1.00`, scored offline against
`analyse_eustack_bundle`). Every eu-stack golden case reproduces its declared
figures exactly.

### Deliberately not "fixed" by moving thresholds

No floor was lowered. `determinism_stability = 1.00` is correct as written:
byte-identical re-runs are the documented guarantee, and relaxing the floor to
make a misconfigured endpoint pass would delete the only signal that detects
real nondeterminism. The correct resolution is operator-side — load the
generation model with a fixed seed at temperature 0 — and Sift's job is to
**say so**, which is where the real bug was.

## 5. Bugs found and fixed during this audit

Diagnosing the above surfaced two independent defects that made `sift doctor`'s
random-seed determinism warning **dead code** (`2281e93`):

1. **Wrong nesting.** It read `default_generation_settings["seed"]`, but
   llama.cpp nests sampler knobs under a `params` sub-dict, so the key was
   always absent.
2. **Wrong predicate.** It tested `seed < 0`, but llama.cpp reports a random
   seed as `UINT32_MAX` (4294967295, i.e. `-1` unsigned), never as a negative
   int.

Either alone was sufficient to suppress the warning on every real llama.cpp
build. The consequence was material: nothing told the operator their endpoint
was nondeterministic, so an endpoint setting presented as a Sift eval failure.

The seed branch had **no test at all**, which is how both survived. Six
regression tests were added; **four fail against the previous code**, including
the negative-seed case — proving the warning was dead in *every* shape, not just
llama.cpp's.

A **temperature warning** was also added, since `temperature > 0` is the other
reason identical prompts diverge and it was not checked at all. Both warnings
now fire against the operator's live endpoint:

```
Warning: server seed is random (4294967295); set a fixed seed for reproducible triage
Warning: server temperature is 0.800000011920929 (> 0); identical prompts can yield
different triage output — load the model at temperature 0 for reproducible triage
```

> Note for the operator: the `sift` on `PATH` is a separately installed uv tool
> (`~/.local/share/uv/tools/sift`) and still carries the old build. The fix is
> live via `uv run sift` from the source tree; reinstall the tool to pick it up
> outside the repo.

## 5b. Deeper finding: Sift cannot reach its own determinism guarantee

Verifying the root cause above surfaced a design gap worth naming, recorded as
`.planning/todos/pending/2026-07-30-generation-sampling-not-controlled.md` and
deliberately **not** actioned in v1.3 (it is new scope, not a v1.3 defect).

`CONTRIBUTING.md:101` and `SPEC.md:219` both promise byte-identical output given
identical "case + config + model + **seed**". But nothing in Sift can set that
seed: `InferenceClient.chat` sends only `messages`, `model` and an optional
`response_format`, and `GenerationConfig` has no `seed` or `temperature` field
(with `extra="forbid"`, an operator cannot supply one through `config.toml`
either). Reproducibility therefore depends entirely on how the model happened to
be loaded — the guarantee is unreachable from Sift.

That the endpoint *would* cooperate was verified directly: sending
`{"seed": 42, "temperature": 0}` in the chat body returned byte-identical
content across repeated calls to the same server that is otherwise
nondeterministic. The control exists at the request level; Sift does not use it.

Consequence for the gate: a green `determinism_stability` today proves only that
the endpoint happened to be deterministic during that run, not that Sift is.
The todo proposes optional `generation.seed` / `generation.temperature` config
threaded into the payload only when set (preserving today's request bytes by
default), plus pinning the eval harness to a fixed seed at temperature 0 so the
metric measures Sift.

## 5c. Third bug, surfaced by the archive step itself

Archiving `REQUIREMENTS.md` turned the suite red: three eu-stack vocabulary
tests **parsed the forbidden lock-ownership term out of
`.planning/REQUIREMENTS.md` at runtime** with a regex. A documentation move that
touched no product code broke `test_eustack_rules.py`,
`test_eustack_facts.py` and `test_eustack_report.py`.

That is a design smell worth naming: a product test suite depended on a planning
document, so the D-05 correctness invariant was only as durable as the file
layout of `.planning/`.

Fixed in `270068b` by moving the prohibition into the product as
`sift.pipeline.eustack_vocabulary.PROHIBITED_OWNERSHIP_TERMS`. It gets its own
module rather than living in `eustack.py`, because a shipped invariant asserts
the classifier's own source text contains none of these terms — a module
declaring them as literals would trip its own gate. The new module emits nothing
and is the single declared exception.

No assertion was weakened: the whole-source grep still scopes to the first term
and the runtime output gates still enforce all three. Verified the gate still
bites by injecting the term into `eustack.py` (test fails) and removing it again
(test passes).
