<objective>
Render what 17-02 computed, and close the phase's determinism and honesty gates.
The Markdown report gains a progression section listing only the signatures whose
population changed, ranked by absolute delta, with appeared and vanished
signatures called out and both the step deltas and the overall figure visible
(D-08, D-09). The CSV gains one count column per dump plus the delta columns
(D-05), carrying the matched frame with its index and the leaf frame rather than
the full frames tuple (D-07). Every string cell is proven to pass the
formula-injection guard, the whole bundle is proven byte-identical on re-run, and
the ownership-blind and population-only-phrasing prohibitions are asserted over
strings the renderer actually emits.

Purpose: this is where the phase becomes readable by an engineer rather than by a
test. It is also where the two claims the phase must not make — per-thread
continuity and lock ownership — stop being intentions and become gates.

Output: the progression rendering in `src/sift/render/eustack_report.py`, the
widened CSV, `tests/test_eustack_report.py`, and the multi-dump byte-identity
test in `tests/test_cli_eustack.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `SignatureProgression` string fields -> CSV cell | C++ symbol text and matched-pattern text from the customer's binaries reach a file opened by spreadsheet software |
| `DumpSlice.source_file` -> CSV header cell | a customer-controlled file name becomes a column header, a cell class the base-column guard would otherwise miss |
| rendered report / stdout summary -> operator terminal | symbol text can carry C1 control bytes and bidi overrides |
| computed figures -> engineer's causal conclusion | a report that reads as a per-thread or ownership claim leads an engineer to a conclusion the evidence cannot support |
