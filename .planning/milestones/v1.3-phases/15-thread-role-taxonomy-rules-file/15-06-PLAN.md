Record, each as its own decision with its rationale and the alternative that was rejected:

  - **Rule-major, first-match-wins in file order (D-01).** For each rule in file order, every frame
    is scanned; the first rule matching anywhere wins. Row position IS the precedence knob and there
    is no `priority` field. State why: it is the only loop order under which editing the file
    predictably changes outcomes (success criterion 2), and the only one where a curator can place
    the job-queue rule above a libc-wait rule and have the 44% population read correctly. Rejected:
    frame-major leaf-outward (stack depth becomes the precedence, so the file cannot reorder
    outcomes); deepest-application-frame-first (needs an `is_app_frame()` predicate — a second,
    implicit taxonomy hardcoded in Python and not editable in the rules file). Note the reversibility
    rating: costly — Phases 16-19 build on this order and changing it later silently reclassifies
    every population.
  - **Symbol normalisation splits on the FIRST `@`, not on `@@` (D-05, as refined).** CONTEXT.md
    D-05 is worded `@@GLIBC_x.y.z`, but the reference capture contains three symbols with a SINGLE
    `@` (`clock_nanosleep@GLIBC_2.2.5`, `cnd_timedwait@GLIBC_2.28`,
    `pthread_rwlock_rdlock@GLIBC_2.2.5`); a literal `@@` split would leave those build-brittle,
    which is precisely what D-05 exists to prevent. Record the measurement: 3,552 frames carry
    `@@GLIBC` suffixes across 3 symbols; signature counts are 93 raw, 93 GLIBC-stripped, 88
    templates-stripped — so template argument lists are KEPT, because stripping them collapses the
    93 the roadmap cites.
  - **Match kinds are exact / prefix / contains, with `exact` the default (D-09).** Looseness is
    never accidental; every `contains` is a word a curator typed and a reviewer can grep for. Tie
    this explicitly to ADR 0013's bare-substring collision, and state the honest difference in
    scale: that ADR's three-character marker was matched against 64 KB of arbitrary content, whereas
    a pattern here is matched against one symbol of tens of characters — the risk is real but
    smaller. Record `fnmatch` as the documented escape hatch that is deliberately NOT added now.
  - **`unclassified` is the sole residual and is illegal as a rule role (D-02, D-12).** Its rate is
    the rules-drift signal. Record why `running` is rule-matched rather than the default: a residual
    `running` would silently label every unrecognised stack as working, which is the guess EUS-02
    forbids, and would drive the unclassified count to near-zero, hiding the signal criterion 3
    exists to expose.
  - **`no resolvable frame` is a reported reason within `unclassified`, not a sixth role.** D-07
    requires the split; success criterion 1 requires exactly five buckets to partition the
    population. A reason field satisfies both. Record that an unresolvable frame stays in the
    signature tuple (it is part of the stack's identity) but is never a match candidate.
  - **The shared-ancestor ordering rule.** Any rule keyed on a task-dispatch or pool-loop frame must
    sit after the rules identifying that task's specific working frames. Record the empirical
    finding: five distinct signatures in the reference capture contain `MSIEvaluationTask::Run`
    alongside a `running`-rule frame. Record the one disclosed residual single-thread case that
    still reads `idle-parked` under the shipped order, and state that D-02's running-rule list is
