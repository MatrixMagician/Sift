<assumption_delta_decision>
The advisory assumption-delta checkpoint fires on a `chosen` signal: the rules-file location moves
from a single packaged constant to a configurable parameter.

- **Primary noun:** the packaged default rules file (`sift.rules/eustack_roles.toml`) remains the
  primary — it is what ships, what the tests assert against, and what `[meta].validated_against`
  describes.
- **Decision: `no-change`.** `rules_path` is an operator escape hatch layered over an unchanged
  primary, not a generalisation that demotes it. This mirrors the shipped `--kb <dir>` seam
  (ADR 0009), which likewise lets the operator point anywhere without displacing a default.
- **Rationale:** promoting "an arbitrary rules file" to primary would mean the shipped taxonomy is
  merely one variant among equals, which would leave `[meta].validated_against` and the CI coverage
  gates with nothing canonical to describe. There is no accepted debt here — a future phase that
  ships a second *named* taxonomy (rather than a user override) would be the trigger to revisit.
</assumption_delta_decision>
