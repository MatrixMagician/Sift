<objective>
Turn per-signature classification into the aggregate surface the rest of v1.3 consumes: role
partition counts, the ranked signature collapse, and the unclassified report a curator uses to
decide which rule to write next.

Purpose: three of the five ROADMAP success criteria are assertions about the aggregate, not about a
single thread — criterion 1 (the five buckets partition the population), criterion 3 (unmatched
frames counted and reported, never guessed) and criterion 5 (work scales with signatures, not
threads). This plan makes all three executable. It also fixes the two genuinely-unaddressed probe
questions the phase's source artifacts leave open — output ordering on ties, and empty input.

Output: `SignatureGroup`, `EustackAnalysis` and `analyse_eustack()` in
`src/sift/pipeline/eustack.py`, plus their tests.
</objective>

**1. The `no-resolvable-frame` predicate (D-07).** Add a private
`_is_resolvable(symbol: str) -> bool` returning `False` for a normalised symbol that is `??`, is
empty, or matches a bare hexadecimal address (`0x` followed by hex digits and nothing else), and
`True` otherwise. Wire it into `classify_signature` so an unresolvable frame is SKIPPED as a match
candidate while remaining in the signature tuple — the tuple is the stack's identity (D-03), and
dropping unresolvable frames would collapse stacks that differ only in what resolved and would make
it impossible for a report to state how much of the capture lacked symbols. When no rule matched
AND no frame in the signature was resolvable, return `reason="no-resolvable-frame"`; when no rule
matched but at least one frame was resolvable, return `reason="matched-no-rule"`. Both keep
`role="unclassified"` — the split is a reason within the residual bucket, never a sixth role,
because success criterion 1 requires the five buckets to partition the whole population.

**2. `SignatureGroup(BaseModel)`,** frozen, `extra="forbid"`: `frames: tuple[str, ...]` (the
normalised signature, full depth), `thread_count: int`, `role: Role`, `subsystem: str | None`,
`pattern: str | None`, `frame_index: int | None`, `reason: Reason | None`. This is the record
Phase 16 groups over and Phase 17 renders, so it carries the whole D-04 answer to "why did this
thread read as idle-parked?" — role, subsystem, the matched pattern TEXT and the frame index —
answerable from the output alone with no re-run.

**3. `EustackAnalysis(BaseModel)`,** frozen, `extra="forbid"`: `total_threads: int`,
`total_signatures: int`, `threads_by_role: dict[Role, int]`, `signatures_by_role: dict[Role, int]`,
`signatures: tuple[SignatureGroup, ...]` (ALL signatures, ranked), `unclassified: tuple[SignatureGroup, ...]`
(the `role == "unclassified"` subset, same order), `rules_hash: str`, `rules_version: int`,
`rules_validated_against: str`. Both role dicts must always carry all five keys, zero-filled — so
criterion 1's partition is assertable by summing values and so Phase 16 never meets a `KeyError`.

D-15 names it as the artefact a curator needs; it is the full list, never a top-N, and any capping

**4. `analyse_eustack(events, rules, rules_hash) -> EustackAnalysis`.** Signature:
`(events: list[Event], rules: ThreadRoleRules, rules_hash: str)`. Steps:

  - Select thread events with `event.thread is not None` — that is exactly the adapter's own marker
    for a thread record versus a preamble or cap-overflow fallback record, so no second notion of
    "is this a thread" is invented here.
  - Build `collections.Counter[tuple[str, ...]]` over `signature_of(event.raw)` for those events,
    ONE pass. Read `Event.raw`, never `Event.message`: `CONDENSED_FRAMES = 5` caps the message and
    the classifying frame sits 8 to 19 deep, so a message-based classifier would be structurally
    incapable of seeing the frame that decides the role.
  - Call `classify_signature(signature, rules)` exactly ONCE per distinct signature and fan the
    single result out by the signature's thread count. This is the whole of success criterion 5 and
    the reason work scales with 93 signatures rather than 3,902 threads; it also means `classify`
    must never be called from inside a per-thread loop.
  - Rank with `sorted(..., key=lambda g: (-g.thread_count, g.frames))` — thread count descending,
    ties broken ascending on the frames tuple. Use `Counter.items()` and this explicit sort; do not
    rely on `Counter.most_common()`'s tie behaviour and do not iterate any `set` on the output path.
  - Zero-fill both role dicts from the `Role` literal's members so all five keys always exist.
  - Copy `rules.meta.version` and `rules.meta.validated_against` onto the analysis, and carry
    `rules_hash` through verbatim. Do NOT import the store and do NOT write
    `store.set_meta("eustack_rules_hash", ...)` — D-11 defers that write to Phase 17, where a
    command with a case to write to exists. Adding a store import here would acquire a dependency
    this phase does not otherwise need, with no reader until Phase 17.

Keep the module free of any store, CLI, network, LLM or subprocess import. Type hints everywhere;
`pyright` strict; British English.
