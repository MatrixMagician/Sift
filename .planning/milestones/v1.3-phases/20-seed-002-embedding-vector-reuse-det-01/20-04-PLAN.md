This ADR **records a settled decision; it does not re-decide it.** Do not
reopen the question, do not present alternatives as live, and do not weaken

`## Context` — ADR 0014 measured that embedding batch composition perturbs
vectors far above float32 noise: 1385 of 1781 vectors differ between
`embeddings.context` 8192 and 32768, max component delta 4.76e-3, cosine
perturbation max 3.19e-4 / median 1.33e-4 against a minimum spacing to the
nearest distinct exemplar of 1.76e-4, and 8 of 200 exemplars (4%) change
nearest-neighbour identity. The trigger is the batch-layout *transition*, not
the context value. ADR 0014 recorded the three knobs in case `meta` with
overwrite semantics and explicitly deferred vector reuse to v1.3/SEED-002.
Phase 20 implements that reuse, which raises the question this ADR settles:
does changing a recorded knob invalidate the stored vectors?

`## Decision` — three parts, stated as settled:

1. **A batch-knob change does NOT invalidate reuse.** `embeddings.context`,
   `embeddings.batch_size` and `embeddings.max_input_chars` are provenance,
   never a guard; `record_embedding_batch_knobs` remains an unconditional
   overwrite. Not invalidating is precisely what makes a re-run reproducible.
   Invalidating would re-embed under a new batch layout on the first run after
   any reconfiguration, reopening the exact hysteresis SEED-002 exists to
   eliminate. `sift analyze --re-embed` is the explicit operator escape hatch
   for applying a knob change.
2. **A model or dimension change DOES invalidate.** A proven embedding-model
   change (both `meta.embedding_model` and the client's model known and
   differing) discards the cache silently and re-embeds. A dimension change
   keeps the shipped STORE-03 hard error; `--re-embed` drops and rebuilds the
   `vectors` and `kb_vectors` tables at the new width. When model identity is
   unknown on either side, reuse proceeds with a stderr warning, because
   treating unknown as changed would permanently disable the feature against
   any endpoint that does not name its embedding model.
3. **The reuse key is exemplar text under exact equality.** A stored vector is
   found by `chunks JOIN vectors USING (chunk_id)` keyed on `chunks.text`, with
   no Unicode normalisation, no case folding, no trimming and no `COLLATE`
   clause — exact code-point equality over the decoded text. Canonically
   equivalent but not code-point-identical text misses and is re-embedded. The
   asymmetry is deliberate: a miss costs one embed, whereas a normalising
   match could return a vector computed from different bytes than the text
   being clustered. `template_id` was rejected as the key for the same reason —
   `exemplar_event_ids[0]` can change after a re-ingest, so the message behind
   a given `template_id` can change while the id stays fixed. Duplicate stored
   texts resolve to the highest `chunk_id` because the read is explicitly
   ordered.

`## Consequences` — what reuse closes and what it does not. It closes ADR
0014's batch-composition exposure for run 2 onward: there is no second
embedding pass to perturb. It does NOT close it for the FIRST run of a case,
which is still embedded under whatever state the shared endpoint happens to be
in; recording predecessor backend state remains explicitly out of scope, as
ADR 0014 already noted that recording the knobs is necessary but insufficient.
ADR 0008's report-layer determinism scope is unamended and must not be
conflated with this layer — this phase makes 0008's "given an identical
`case.db`" assumption true upstream rather than widening 0008. KB vector reuse
is not implemented; `index_kb` still re-embeds every chunk on every `--kb`
run.

Then update `CONTRIBUTING.md`'s Determinism bullet (around lines 96-112) with
a single sentence, placed with the existing ADR 0008 / ADR 0014 references,
stating that from v1.3 a re-analysis reuses persisted embedding vectors so
run 2 onward performs no second embedding pass, that the first run of a case
remains subject to ADR 0014's exposure, and linking
`docs/decisions/0018-batch-knob-does-not-invalidate-vector-reuse.md`. Do not
delete or weaken the existing ADR 0014 qualification and do not upgrade the
claim to unconditional determinism — the run-1 residual is real and the doc
must keep saying so.
  </action>
