<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ingested artefact → `events` table | Untrusted eu-stack dump text crosses into stored `raw`/`message` here, bounded by `adapters/eustack.py`'s `MAX_EVENT_LINES=256` / `MAX_EVENT_BYTES=65536` caps. |
| `EXCLUDED_FROM_RANKING` → SQL `WHERE source NOT IN (...)` | A module-owned constant becomes SQL parameters in `iter_event_summaries`. |
| stored event text → terminal (`show events`, `analyze` output) | Attacker-influenced symbol/frame text reaches an operator's terminal. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Tampering | `store.EXCLUDED_FROM_RANKING` → `iter_event_summaries` SQL | medium | mitigate | The added member is a module-owned literal, never caller-supplied; the existing `sorted(...)` + `?`-bound construction at `store.py:659-668` is not modified, so no new string interpolation reaches SQL. Task 1 acceptance asserts the diff does not touch `iter_event_summaries`. |
| T-19-02 | Information disclosure | `analyze` falling through to `hypothesise()` on an excluded-source-only case | low | accept | The fall-through sends the already-shipped Phase-18 fact block to the configured localhost endpoint — the same data `sift analyze` already sends today for any case containing eu-stack events. No new data class crosses the boundary; the endpoint guard (`InferenceClient` loopback/RFC1918 check) is untouched. |
| T-19-03 | Tampering | terminal rendering of eu-stack frame text via `show events` | low | accept | Already mitigated upstream and unchanged by this plan: `render/_util.sanitise` strips C0/DEL/C1 control characters on every DB-sourced render path (T-04-01, shipped Phase 2). This plan adds assertions over that path, not a new writer. |
| T-19-04 | Denial of service | `next(iter(store.iter_event_rows()), None)` on a very large case | low | accept | The probe reads at most one row from a streaming cursor and is strictly cheaper than the `query_events()` alternative it replaces in the design space; it runs once per `analyze` invocation. |
| T-19-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable — this plan installs zero packages (RESEARCH.md "Package Legitimacy Audit: Not applicable"). No `uv add`, no dependency change; `uv.lock` is untouched, which the wave gate confirms via `git diff --stat`. |
