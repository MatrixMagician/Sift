Eu-stack dump format (verbatim shape, from `tests/fixtures/eustack/threaddump.txt`; regexes confirmed
against `src/sift/adapters/eustack.py:44-58`):
```
-- sanitised eu-stack capture; addresses and symbols masked --
2026-07-18T09:15:30+00:00 eu-stack backtrace of process castorserver
PID 715821 - castorserver
TID 715821:
#0  0x00007f0000000001 clock_nanosleep@@GLIBC_2.17
#1  0x00007f0000000002 __nanosleep
```
- `_TID_RE = r"^TID (\d+):"`, `_FRAME_RE = r"^#(\d+)\s+0x([0-9A-Fa-f]+)\s+(.+)$"`.
- Sniff needs BOTH `_SNIFF_TID_RE` (`^TID \d+:`) and `_SNIFF_FRAME_RE` (`^#\d+\s+0x`) to match in the
  sniffed head, else the file falls through to `genericlog` with no `source == "eustack"` tag and the case
  silently proves nothing (RESEARCH Pitfall 4).
- A thread block ends at the next `TID` line or at `MAX_EVENT_LINES = 256` / `MAX_EVENT_BYTES = 65536`.

Signature semantics that make the mutation twin meaningful (`src/sift/pipeline/eustack.py`, Phase 15):
- A thread's signature is the ordered tuple of every frame's NORMALISED symbol. Instruction addresses are
  excluded from the signature; `@@GLIBC_x.y.z` suffixes and ` - <lib> <src>:<line>` tails are stripped;
  template argument lists are kept.
- Therefore renumbering TIDs and changing instruction addresses cannot change a signature by construction,
  and reordering thread blocks cannot change a population count. The twin test is what stops a future
  change from quietly making either of those matter.

Figure surface the truth blocks pin (`analyse_eustack_bundle` → `EustackBundle`):
- `bundle.analysis.total_threads: int`
- `bundle.saturation.pools` → `PoolOccupancy{subsystem, total_threads, idle_threads, busy_threads, occupancy, signature_count}`
- `bundle.saturation.dependencies` → `DependencyWait{subsystem, thread_count, signature_count}`
- `bundle.saturation.flags` → `SaturationFlag{dimension, severity, value, unit, warn, critical, message}`

`EustackThresholdsConfig` defaults (`src/sift/config.py:144-146`):
`unclassified_thread_pct` warn 5.0 / critical 15.0; `no_resolvable_frame_pct` warn 5.0 / critical 15.0;
`lock_convergence_count` warn 5.0 / critical 20.0.

Sensitivity-test analog: `tests/test_eval_cases.py::test_mcm_denial_citation_validity_is_mcm_sensitive`
(~line 238) — `monkeypatch.setattr(<module>, <symbol>, <neutered>)`, run the case twice, assert the metric
crosses its floor only with the mechanism intact.

`sift eval`'s `--suite` argument accepts any directory containing case sub-directories with a
`truth.yaml` (`src/sift/cli.py:1485-1491` builds `case_dirs` by scanning it), so a scoped eu-stack-only
suite can be assembled in `tmp_path`.
