<objective>
Turn the 2.4 MB out-of-repo reference capture into a small, committable, signature-preserving
derivative that reproduces all 93 distinct stack signatures in CI — and commit the mechanical script
that produced it, so the fixture's provenance is auditable rather than asserted.

without shipping a customer diagnostic artefact from a tool whose entire premise is not shipping
customer diagnostics anywhere. Committing the extraction script — which contains no role, rule or
classification logic at all — is what makes "this fixture was not authored to match the detector"
a checkable fact rather than a claim.

in CI) and `tests/fixtures/eustack/reference_capture_derivative.txt` (about 145 KB, 93 signatures).

This plan has zero file overlap with every other Phase 15 plan, so it runs in wave 1 alongside the
tracer and the config wiring.

Write `tests/fixtures/eustack/derive_reference_capture_derivative.py` — a manual, offline tool that
mechanically extracts a signature-preserving derivative from an out-of-repo eu-stack capture. It is
never run by CI (its input is not in the repo) and never imported by a test.

Module docstring must state, explicitly: this is a manual provenance tool, not test code; it needs a
local out-of-repo capture that is deliberately not committed (2.4 MB per dump, carrying a customer
environment identifier); it contains no role, rule, subsystem or classification logic whatsoever, so
the fixture it produces cannot have been shaped by the detector — the named failure mode
`.planning/research/PITFALLS.md` Pitfall 5 describes and EUS-12 guards against; and it records the
exact invocation used to produce the committed fixture.

Behaviour:

  - `main()` takes the input capture path and the output fixture path as `argparse` arguments. Keep
    it small — no Typer, no click; this is not part of the CLI surface.
  - Read the capture and group it into thread blocks using the same rule the shipped adapter uses:
    a line matching `TID <n>:` starts a new block, and every subsequent line accrues to it until the
    next header. Import `_TID_RE` from `sift.adapters.eustack` rather than writing a second regex.
  - Compute each block's signature by calling `signature_of` imported from
    `sift.pipeline.eustack`. Do not define a second notion of signature in this file — the
    fixture's signature identity must be the same function the classifier uses, or the fixture can
    silently drift from what it is supposed to preserve.
  - Group blocks by signature and count threads per signature.
  - Emit, per signature, the FIRST N thread blocks verbatim (raw text, `TID <n>:` header plus every
    frame line, unchanged), where N is 5 for the three signatures with the highest thread counts and
    1 for all others. This hybrid is RESEARCH.md's own recommendation: cap 1 is the size floor that
    satisfies criterion 5 (93 of 93 signatures) at a measured 143,281 bytes, and the selective cap 5
    is what makes the broadcast-one-classification-to-N-threads path genuinely exercised rather than
    assumed.
  - Sanitisation, applied to the OUTPUT only: rewrite every `TID <n>:` header to a sequentially
    renumbered synthetic TID starting at 100001; emit a synthetic process header line
    `PID 999999 - process`; emit NO timestamp line at all, because inventing one would contradict
    the project's own no-invented-timestamps principle (ADR 0012, EUS-08); and emit no filename,
    hostname, environment slug or date anywhere. The frame lines themselves are pure C++ symbol text
    and pass through byte-verbatim — RESEARCH.md confirmed no string literals, hostnames or user
    data appear in any frame across the sampled signatures.
  - Emit a leading provenance preamble as double-dash-prefixed lines, matching the convention the
    shipped `tests/fixtures/eustack/threaddump.txt` already uses. The preamble states: this is a
    derived, sanitised fixture and not a capture; the per-signature cap policy actually applied; the
    total signature count and total thread count in the derivative; the original capture's totals
    (3,902 threads and 93 signatures); and the exact command line that produced it. The adapter
    treats this preamble as a `thread=None` fallback event, so it can never contaminate a
    thread-level assertion.
  - Print the resulting signature count, thread count and byte size to stdout so the operator can
    check them against the expected figures.

Type hints everywhere (`pyright` strict covers `tests/`); `ruff` lint clean; British English.
