<objective>
Make reuse safe to trust: invalidate the whole cache on a proven embedding-model
change, warn loudly when model identity cannot be verified, give the operator
`--re-embed` as the explicit cache bypass, and refuse to splice vectors whose
width no longer matches the endpoint.

Purpose: plan 20-01 proved reuse works. This plan makes it correct in the
cases where reusing would be wrong or unprovable. It also lands the `announce`
callback seam that plan 20-03's destructive dimension announcement depends on.
Output: the D-03/D-04 identity gate, the `--re-embed` flag at unchanged
dimension, and the stored-width discard guard.
</objective>

Add two keyword-only parameters to `cluster_and_label` in
`src/sift/pipeline/cluster.py`: `re_embed: bool = False` and
`announce: Callable[[str], None] | None = None`. Import `Callable` from
`collections.abc` under the existing `TYPE_CHECKING` convention used in the
module. `announce` is the pipeline's ONLY operator-facing output seam — the
module keeps its typer-free/print-free contract (`retrieve.py:6`) and never
performs a direct standard-output call.

Implement the identity gate immediately after the reuse-map read at the top of
the function, BEFORE the `client.embed(...)` call and before any write. Read
`stored_model = store.get_meta("embedding_model")` and
`client_model = client.embedding_model`. The property must be read here, not
after the embed: pre-embed it resolves to the configured
`config.embeddings.model` with no network call, which is exactly the value
D-03's comparison needs; read after the embed it prefers the server-reported
name instead and the decision would no longer precede the reuse read
(RESEARCH Pitfall 1). Three outcomes:

- Both non-None and different — a PROVEN model change. Replace the reuse map
  with an empty dict so every exemplar is re-embedded. Emit no message: D-03
  states no operator action is required, and the `Embeddings: N new, 0 reused`
  line from plan 20-01 already makes the full re-embed visible.
- Either side None — identity is unverifiable. Reuse PROCEEDS (treating
  unknown as changed would permanently disable the feature on any endpoint
  that does not name its embedding model, and it would make the feature appear
  to work while silently never firing). Call `announce` with a message that
  states, in British English, that stored embedding vectors were reused
  without a verifiable model identity, that a model change therefore cannot be
  detected, and that `sift analyze --re-embed` forces a full re-embed. The
  message must contain the exact fragment `without a verifiable model identity`
  so a test can pin it. Emit it only when the reuse map is actually non-empty
  — a first run with nothing to reuse has nothing to warn about.
- Both non-None and equal — reuse proceeds silently.

Add the stored-width discard guard after `dim` is computed. If the reuse map
is non-empty and any reused vector's length differs from `dim`, discard the
entire reuse map and re-embed every text (rebuilding `miss_texts` as the
deduplicated full `texts` list and calling `client.embed` once more), setting
`embedded_count` to the new deduplicated miss count and `reused_count` to the
remainder. Without this guard a dimension change produces a ragged list that
fails inside `normalize(np.asarray(vectors, dtype=np.float64))` with an opaque
numpy error BEFORE `ensure_vectors_table` can raise its clean STORE-03
`embedding dimension mismatch` message — the operator must keep getting the
error that names both dimensions, because that error is what tells them to
reach for `--re-embed` (the recovery path plan 20-03 builds).

Note the residual D-04 consequence and do not try to close it here: on an
all-hit run where model identity is unknown on both sides AND the endpoint's
dimension has changed, no embed call happens, so the width guard never fires
and the old vectors are reused at the old width. That is precisely the risk
D-04 accepts in exchange for the feature working at all against an endpoint
that names no model, and the warning is the only thing standing between the
operator and it — which is why the warning must be un-swallowable.

In `src/sift/cli.py`, bind the callback at the call site (currently around
line 943, inside the `Progress` block) as
`announce=lambda message: err_console.print(message, highlight=False, markup=False, soft_wrap=True)`.
`err_console` is the same `Console(stderr=True)` instance that owns the
transient `Progress` live region, so rich moves the live region below the
printed line instead of overwriting it — a bare stderr write during a live
display can be erased by the next bar redraw on a TTY. `soft_wrap=True`
disables width-dependent line breaking so the message stays one line and a
substring assertion cannot be defeated by terminal width; `markup=False` and
`highlight=False` keep the text literal, consistent with the T-03-23
discipline that untrusted text never enters a rich renderable (this message is
our own literal plus nothing else, but the flags cost nothing and keep the
rule uniform).

| inference endpoint → `client.embedding_model` | The endpoint may name a model, name a different one, or name none at all. |
