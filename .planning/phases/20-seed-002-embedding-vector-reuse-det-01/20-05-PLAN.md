<planning_correction_to_research>
**RESEARCH.md and PATTERNS.md both sketch the wrong change for D-10, and
following either would duplicate shipped code.** Both propose adding a
`client.props().get("n_ctx")` resolution to `cli.py` around line 989, next to
`ctx_fallback=config.generation.context or _TRIAGE_CTX_FALLBACK`.

Verified against current HEAD: `src/sift/pipeline/hypothesise.py:248-255`
already contains `_ctx_tokens(client, fallback)`, which does exactly that —
`n = client.props().get("n_ctx")`, used when it is a positive int, else the
fallback — and `hypothesise` already calls it at line 482. The `/props`
consultation D-10 describes as missing is **already shipped**. Adding the
sketched block would create a second resolution site and a second HTTP GET per
run (`props()` performs an uncached `GET`; only `has_props` memoises a bool).

The two genuine, verified deltas are:

1. **A precedence inversion.** `cli.py:989` passes
   `ctx_fallback=config.generation.context or _TRIAGE_CTX_FALLBACK`, and
   `_ctx_tokens` then prefers the server's `n_ctx` **over** that value. An
   explicitly configured `generation.context` is therefore silently overridden
   by whatever the endpoint reports — the inverse of D-10's "consult
   `client.props()` **when** `config.generation.context` is `None`", and the
   inverse of the project's documented precedence in `CLAUDE.md`.
2. **The missing warning.** Nothing tells the operator that the budget was
   estimated rather than discovered. That is the entire point of the folded
   todo: Lemonade serves no `/props`, so today the 8192 default is assumed in
   silence while the loaded model's real window may be far larger or smaller.

This plan implements those two deltas and reuses `_ctx_tokens` rather than
duplicating it.
</planning_correction_to_research>

  <action>
Add a module-level helper to `src/sift/cli.py`, placed next to the
`_TRIAGE_CTX_FALLBACK` constant it uses:
`_resolve_generation_ctx(configured: int | None, client: InferenceClient) -> tuple[int, str | None]`.
It returns the context window to use and an optional warning string, and it is
the SINGLE place the generation context is resolved. Logic:

- `configured` is a positive int → return `(configured, None)`. An explicitly
  pinned value is a deliberate operator decision, is never overridden by the
  server, and is never warned about.
- otherwise read `client.props().get("n_ctx")` exactly once; when it is a
  positive int → return `(that value, None)`.
- otherwise → return `(_TRIAGE_CTX_FALLBACK, <warning>)`, where the warning is
  a British-English sentence stating that the generation prompt budget is
  estimated rather than discovered, that the endpoint served no usable context
  size, naming the fallback token count, and pointing at `generation.context`
  as the way to pin it. It must contain the exact fragment
  `estimated rather than discovered` so a test can pin it.

Returning the warning rather than printing it is deliberate: it makes the
whole decision unit-testable without a `CliRunner` and without depending on
how the pinned Click version separates stdout from stderr, and it keeps the
resolution a pure function.

In `analyze`, immediately before the `hypothesise(...)` call and therefore
AFTER the `Progress` context has exited (so no live display can overwrite it),
call the helper, emit the warning when non-None with
`print(warning, file=sys.stderr)` — matching the shipped degraded-run warning
style at `cli.py:1019` — and pass `ctx_configured=<resolved int>` to
`hypothesise`. Replace `ctx_fallback=config.generation.context or _TRIAGE_CTX_FALLBACK`
at line 989 with `ctx_fallback=_TRIAGE_CTX_FALLBACK`: the fusion of the
configured value into the fallback argument is what created the precedence
inversion, and the configured value now travels on its own parameter. Because
the CLI always passes a concrete resolved int, `_ctx_tokens` short-circuits and
never issues a second `/props` request on the analyze path.

Leave the ADR 0005 exit-code contract, the summary block and every other part
of `analyze` untouched.

Add to `tests/test_cli.py`: `test_resolve_generation_ctx_prefers_configured`,

idiom (no `CliRunner`, no stream-separation question). Assert the returned int
and the presence or absence of the warning, pinning the exact fragment
`estimated rather than discovered`. Add one end-to-end
`test_analyze_exits_normally_without_props` that invokes
